# Glossary

_Last updated: 2026-06-23_

Shared terms used across these docs. Where a term has a fuller treatment elsewhere, the
entry links to it.

- **CI (continuous integration)** — Automated checks that run on GitHub when you open a pull
  request or push to `main`. Here, GitHub Actions validate and render the Quarto data
  stories so a broken story is caught before it ships.

- **CLI (command line)** — Tools you run by typing commands in a terminal, e.g. `zola serve`
  or `scripts/build-stories.sh`.

- **Companion stub** — The small `content/stories/<slug>.md` file that gives a Quarto data
  story its card in the `/stories/` grid (title, description, date, author, tags).
  Auto-generated by `build-stories.sh` from the story's front matter, then hand-edited to set
  tags.

- **Design tokens** — The site's shared palette and fonts, defined once in
  `sass/_tokens.scss` and reused everywhere (including in story charts) so the whole site
  stays on-brand.

- **Fragment** — The self-contained chunk of HTML a Quarto data story renders to: just the
  story content, without the site shell. The site embeds it into a normal page so the story
  picks up the shell and styles.

- **Freeze** — Quarto's cache of a story's computed results (`quarto/_freeze/`). It lets the
  site rebuild a story's figures without re-running the analysis code. Pass `--force` to
  `build-stories.sh` to re-run from scratch.

- **Front matter** — The metadata block at the top of a content file: between `+++` (TOML)
  for Markdown pages, or `---` (YAML) for Quarto `.qmd` files. Holds title, date,
  description, tags, and so on.

- **Markdown story** — A story hand-written directly in `content/stories/<slug>.md`. Contrast
  with a Quarto data story.

- **Netlify** — The hosting service that rebuilds and publishes the site automatically when
  you push to `main`.

- **Quarto data story** — A story authored in [Quarto](https://quarto.org) (`.qmd`) whose
  charts, maps, and tables are generated from R/Python analysis code. Contrast with a
  Markdown story. See [Authoring a Quarto data story](quarto.md).

- **Sass / SCSS** — The styling language the site's CSS is written in; Zola compiles it
  automatically on build.

- **Site shell** — The page furniture that wraps every page's content: the header/nav and the
  footer.

- **Slug** — The URL-friendly name of a page, taken from its file or folder name. A story at
  `quarto/stories/economic-mobility/` is served at `/stories/economic-mobility/`.

- **Taxonomy** — Zola's system for grouping pages by a shared attribute. Here it powers tags:
  each tag becomes a filter button and its own listing page.

- **Tera** — Zola's HTML templating language — the `templates/*.html` files.

- **Zola** — The [static site generator](https://www.getzola.org/) that turns the content and
  template files into the published website.
